## Цель проекта

Создать веб‑приложение на Django, которое позволяет пользователям управлять рассылками сообщений для клиентов.
Приложение должно включать функциональность для создания, просмотра, редактирования и удаления рассылок, а также
отправки сообщений по требованию.

## Часть 1. Разработка сервиса

### 1. Управление клиентами

Реализовать CRUD‑операции для получателей рассылки (клиентов).

**Модель «Получатель рассылки»:**

* `email` (строка, уникальное);
* `full_name` (строка);
* `comment` (текст).

### 2. Управление сообщениями

Реализовать CRUD‑операции для сообщений.

**Модель «Сообщение»:**

* `subject` (строка) — тема письма;
* `body` (текст) — тело письма.

### 3. Управление рассылками

Реализовать CRUD‑операции для рассылок.

**Модель «Рассылка»:**

* `start_time` (`datetime`) — дата и время начала отправки (обязательно);
* `end_time` (`datetime`) — дата и время окончания отправки (обязательно);
* `status` (строка) — статус:
    * `'Создана'` — текущая дата раньше `start_time`;
    * `'Запущена'` — текущая дата между `start_time` и `end_time` (включительно);
    * `'Завершена'` — текущая дата позже `end_time`.
* `message` (внешний ключ на модель «Сообщение»);
* `recipients` (связь «многие ко многим» с моделью «Получатель»).

**Требования к валидации:**

* `start_time` не может быть в прошлом;
* `start_time` должен быть раньше `end_time`.

### 4. Отправка сообщений по требованию

Реализовать возможность вручную запускать рассылку через интерфейс пользователя и/или командную строку (рекомендуется в
`service.py`).

**Логика отправки:**

NaN. Проверка времени: отправка разрешена, если текущее время между `start_time` и `end_time`.

NaN. Определение получателей: выбор всех клиентов, связанных с рассылкой.

NaN. Отправка писем:

    - использование `send_mail()` для каждого клиента;
        
    - создание записи о попытке со статусом `'Успешно'` при успехе;
        
    - создание записи со статусом `'Не успешно'` и текстом ошибки при ошибке.

### 5. Попытки рассылок

Для каждой попытки отправки сохранять:

- `attempt_time` (`datetime`) — дата и время попытки;

- `status` (строка): `'Успешно'`, `'Не успешно'`;

- `server_response` (текст) — ответ почтового сервера;

- `mailing` (внешний ключ на модель «Рассылка»).

### 6. Главная страница

Отобразить на главной странице:

- общее количество созданных рассылок;

- количество активных рассылок (статус `'Запущена'`, текущая дата между `start_time` и `end_time`);

- количество уникальных получателей (общее число клиентов в системе).

# Сервис управления рассылками

Веб‑приложение на Django для управления рассылками сообщений клиентам: создания, просмотра, редактирования, удаления
рассылок и отправки сообщений по требованию.

## Описание проекта

Сервис предназначен для автоматизации вспомогательных («прогревающих») рассылок — информирования и привлечения клиентов.
Позволяет пользователям управлять рассылками, администрировать данные и получать статистику.

Проект состоит из двух частей:

1. **«Разработка сервиса»** (часть 1) — создание базовой структуры, интерфейса, моделей и CRUD‑операций.
2. **«Расширение функционала»** (часть 2) — добавление новых возможностей: форм, аутентификации, прав доступа,
   кеширования.

## Функциональные возможности

### Часть 1. Разработка сервиса

**1. Управление клиентами (получателями рассылок):**

* добавление, просмотр, редактирование, удаление получателей;
* модель «Получатель рассылки»:
    * `email` (строка, уникальное);
    * Ф. И. О. (строка);
    * комментарий (текст).

**2. Управление сообщениями:**

* добавление, просмотр, редактирование, удаление сообщений;
* модель «Сообщение»:
    * тема письма (строка);
    * тело письма (текст).

**3. Управление рассылками:**

* добавление, просмотр, редактирование, удаление рассылок;
* модель «Рассылка»:
    * `start_time` (datetime, обязательно) — дата и время начала отправки;
    * `end_time` (datetime, обязательно) — дата и время окончания отправки;
    * `status` (строка) — статус (`'Создана'`, `'Запущена'`, `'Завершена'`), вычисляется динамически;
    * `message` (внешний ключ на модель «Сообщение»);
    * `recipients` (связь «многие ко многим» с моделью «Получатель»).

**4. Отправка сообщений по требованию:**

* запуск рассылки через интерфейс пользователя или командную строку;
* проверка условий отправки (время между `start_time` и `end_time`);
* отправка писем с помощью `send_mail()`.

**5. Попытки рассылок:**

* сохранение данных о каждой попытке:
    * `attempt_time` (datetime);
    * `status` (`'Успешно'`, `'Не успешно'`);
    * `server_response` (текст);
    * `mailing` (внешний ключ на модель «Рассылка»).

**6. Главная страница:**

* отображение статистики:
    * общее количество рассылок;
    * количество активных рассылок (статус `'Запущена'` и текущая дата между `start_time` и `end_time`);
    * количество уникальных получателей.
